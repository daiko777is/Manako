Manakō — Arquitectura del sistema

Artefacto visual de la especificación técnica (§2, §3, §5, §6). Angular 18 + RxJS + Signals · NestJS · Supabase (Postgres + Auth + RLS) · Stripe · Mux / Cloudflare Stream.

1 · Arquitectura general

Decisión clave (spec §2): Supabase cubre Auth + DB + RLS; la API NestJS centraliza la lógica de negocio que nunca debe vivir solo en el cliente: emisión de URLs firmadas de video, concesión de acceso tras webhooks de Stripe, RBAC y rate limiting. El backend es stateless → escalado horizontal detrás de balanceador. Frontend en Vercel/Netlify/CF Pages; API en Railway/Render/Fly (Docker incluido en apps/api/Dockerfile).

2 · Flujo de compra (pago único con Stripe)

Nunca se confía en el frontend (spec §3.6): la inscripción de pago la crea exclusivamente el webhook verificado. Idempotencia en 3 capas: tabla stripe_webhook_events, UNIQUEs de session_id/payment_intent y transiciones de estado comprobadas. Cursos gratis: inscripción inmediata vía POST /payments/checkout (o RLS en BD).

3 · Reproducción, bloqueo secuencial y tracking de progreso

Doble validación (spec §6.2): el Guard de Angular da la UX (candados), pero la autoridad es la API — que replica lesson_is_unlocked() antes de firmar la URL. La URL expira en minutos y el watermark con el email disuade la redistribución (spec §6.4). El progreso se persiste con throttleTime(5000) + buffer local: nunca 1 request por segundo (spec §7.4).
